# Отчет об испытаниях: Этап 3 (Интеграция с базой данных)

**Дата:** 2026-11-10
**Статус:** ✅ Успешно завершено
**Расположение артефактов:** `src/backend/`, скриншоты в `artifacts/reports/logs/`

## 1. Цель этапа

Проверить способность Python-парсера не только извлекать данные из бинарного потока, но и сохранять их в постоянное хранилище. Для изоляции логики работы с БД выбран паттерн "Репозиторий". В качестве СУБД для MVP используется SQLite.

## 2. Методика испытаний

1. **Архитектура:** Создан интерфейс `TelemetryRepository` и его реализация `SQLiteRepository`. Это позволяет в будущем безболезненно перейти на PostgreSQL.
2. **Скрипт (Python):** Скрипт `parser.py` инициализирует БД (создает таблицы при первом запуске), принимает UART-фрейм, проверяет CRC, парсит строку и вызывает метод `repo.save_telemetry()`.
3. **Верификация:** Просмотр содержимого БД через сторонний инструмент **DB Browser for SQLite**.

## 3. Результаты испытаний

### 3.1. Логи работы парсера

Скрипт успешно принимает данные, проверяет CRC и записывает в базу. Ошибок нет.

```text
[19:03:02] [+] DB Save OK | 01 | {'temperature': 22.0, 'humidity': 53.5}
[19:03:07] [+] DB Save OK | 01 | {'temperature': 22.2, 'humidity': 43.7}
```

### 3.2. Состояние таблицы `devices`

При каждом новом пакете обновляется время `last_seen_at`, а статус устройства выставляется в `online`. Логика UPSERT работает корректно.
_(Скриншот: [artifacts/reports/logs/db-data-devices.png](./logs/db-data-devices.png))_

![Состояние таблицы `devices`](./logs/db-data-devices.png)

### 3.3. Состояние таблицы `telemetry`

В таблицу записано 58 строк. Поле `payload` содержит валидный JSON, сформированный из входящей строки. Время записи (`ts`) фиксируется с точностью до микросекунд.

## 4. Выводы

1.  **Паттерн "Репозиторий" доказал свою эффективность.** Код парсера не содержит SQL-запросов, он лишь вызывает методы абстракции.
2.  **Данные успешно сохраняются.** Система готова к тому, чтобы этими данными начал пользоваться веб-интерфейс.
3.  **MVP (Minimum Viable Product) полностью готов.** Система выполняет главную функцию ТЗ: собирает телеметрию и сохраняет её в хранилище.
